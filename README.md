# Бот Dream Shore

Discord-бот на Node.js. Использует `rules.txt`, выдаёт роль участника через реакцию на embed, поддерживает ручные предупреждения и сообщает модераторам о сообщениях с объективными признаками возможного нарушения.

## Запуск локально

Нужен Node.js 22.13 или новее.

1. Отзовите старый токен бота в Discord Developer Portal и создайте новый.
2. Установите зависимости:

   ```powershell
   npm install
   ```

3. Задайте токен в PowerShell и запустите бота:

   ```powershell
   $env:DISCORD_TOKEN = "новый_токен_бота"
   npm start
   ```

Токен хранится только в переменной окружения. Не помещайте его в исходный код, Git или `.env.example`.

## Развёртывание

Подключите Git-репозиторий к хостингу, выберите Node.js 22.13+ и задайте команду запуска `npm start`. В настройках хостинга добавьте переменную окружения `DISCORD_TOKEN`.

Бот не открывает HTTP-порт; для него нужен хостинг фоновых процессов (worker/background service), а не только веб-сервис. Если хостинг предоставляет постоянный диск, задайте `DB_PATH` на путь к файлу SQLite на этом диске. Без постоянного диска локальная база может сбрасываться при перезапуске или новом деплое. `bot_data.sqlite3` намеренно исключён из Git: не публикуйте базу с данными участников.

## Настройка Discord

В Discord Developer Portal включите для приложения **Server Members Intent** и **Message Content Intent**. Пригласите бота с разрешениями **View Channels**, **Send Messages**, **Embed Links**, **Add Reactions**, **Read Message History** и **Manage Roles**. Поднимите роль бота выше ролей «Участник», «Варн №1», «Варн №2» и «Забаненный». Команды требуют прав `Manage Server` (`!в`) или `Manage Messages` (`!варн`).

ID сервера, ролей и канала модерации настроены в `index.js` для Dream Shore. Канал модерации должен быть текстовым, а боту и роли модератора необходимо дать к нему доступ.

## Команды

- `!в` или `!verify` — разместить embed верификации. Пользователь получает роль «Участник» после нажатия ✅ именно под последним созданным сообщением.
- `!варн @пользователь 1.1` — выдать предупреждение по номеру правила из `rules.txt`. Первое предупреждение даёт роль «Варн №1», второе — «Варн №2», третье — «Забаненный». Третье предупреждение назначает только роль и **не** банит участника на сервере.
- `!правила` — показать перечень правил; `!правила 1.1` — показать конкретное правило.

Счётчик предупреждений и ID сообщения верификации сохраняются в `bot_data.sqlite3` (или в файле из `DB_PATH`). Если рядом осталась база от Python-версии, Node.js-бот продолжит использовать её: схема SQLite сохранена.

## Автомодерация и ограничения

Автомодерация работает в текстовых сообщениях сервера и только **передаёт подозрительные случаи** роли модераторов в указанный канал: повтор одинакового сообщения, чрезмерный капс, массовые упоминания, Discord-ссылки-приглашения и вложения с исполняемыми расширениями. Бот не удаляет такие сообщения и не выдаёт за них предупреждений автоматически.

Правила оскорблений и контекста, содержимом изображений/видео, профилях, личных сообщениях, голосовом поведении, обходе блокировок и подобных ситуациях нельзя надёжно определить по одному текстовому сообщению. Они требуют проверки модератором; бот не читает личные сообщения, профили и голосовые каналы. Любое автоматическое сообщение в канале модерации является сигналом для проверки, а не подтверждением нарушения.
